PayCheck

Ask whether a merchant, URL, or wallet is safe to pay before an agent sends money.

Deterministic score. No payment execution. No wallet keys. Policy version 1.

Trusted · 100

https://api.openai.com is on the allowlist of known AI and developer APIs.

Unknown or suspicious

A new or random domain is never trusted, even if you reword the purpose.

Block

http://1.2.3.4, localhost, burn addresses, and typosquats are refused.

What it checks

Pass a domain, an https URL, or a 0x wallet. PayCheck returns a score from 0 to 100, a verdict (trusted, unknown, suspicious, or block), reasons, and a recommended action.

Trusted is reserved for the published allowlist over https on port 443. Wallets are never trusted in v1: there is no chain analysis. Domain age comes from public RDAP. If that lookup fails, the age is unknown. PayCheck does not invent one.

amount_usd, category, and any purpose text are discarded. They do not change the score and they are not stored.

MCP

Streamable HTTP on POST /mcp. Protocols 2025-06-18 and 2025-03-26. Tools: check_merchant, get_quota, get_api_key.

{
  "mcpServers": {
    "paycheck": {
      "type": "http",
      "url": "https://YOUR-WORKER.workers.dev/mcp"
    }
  }
}

Call get_api_key once and store the key. Do not call it every turn. Glama can also launch the stdio build: node dist/stdio.js.

What it will not do

  • Send a payment or sign a transaction.
  • Hold a wallet key. PAY_TO only receives the optional x402 micropayment for an over-cap check.
  • Upgrade a verdict because the prompt asked nicely.
